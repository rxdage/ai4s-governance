# 03 · 入库：单源库、来源链、只增不改

> 一句话：**测出来的进 `data/`，算出来的进 `derived/`；复制入库、算哈希、写清单、设只读；
> 入库后永不原地改，变更 = 同 T、RUN+1、整份重入。**

## 1. 库长什么样

```
library/
├── data/            # 测出来的：仪器采集、人写的记录/参数/协议/报告
│   └── R0007/       # 批次目录，批内平铺
├── derived/         # 算出来的：拟合、汇总、统计、AI 分析
│   └── R0007/       # 与 data/ 同构；sidecar 与数据文件同目录
└── index/
    └── manifest.tsv # 账本：一行一个文件，只追加
```

- 落点固定 `分区/R{4位}/完整文件名`，**一共三层**，不再按人/类型/晶圆分层。
- 平铺是有意的：同名文件必然落在同一路径，当场撞出来；“库内唯一”这条保护靠的就是它。
- **库按物理对象组织，不按组织架构组织。** 人换了、岗位调了，库不用动。
  “谁交的”记在 manifest 的 `src_abs` 与入库批次里，不进文件名。
- `R0000/` 是库级件目录：配方、协议、参数表、外购对照、台账。

## 2. 原始 vs 衍生：为什么必须分开

| | 原始采集 | 分析结果 |
|---|---|---|
| 来源 | 仪器；同条件重测能复现 | 脚本或 AI 算的 |
| 出错方式 | 设备故障（通常看得出来） | 参数选错、样本选偏、AI 幻觉（**看不出来**） |
| 可复现性 | 高 | 脚本尚可；AI 同一个问题问两次可能不一样 |
| 谁背书 | 设备 + 操作者 | **复核的那个人** |

混在一起最坏的后果，是**几个月后没人分得清哪个数字是测的、哪个是算的**，
然后有人拿一个没复核的 AI 拟合结果去写报告。

**分流不看文件名、不看人放在哪，只看 `types.yaml` 里的 `derived` 标志位。**
放错分区当场拒收（`PARTITION_MISMATCH`），工具不替人猜。

## 3. 衍生数据的三件套

### 3.1 sidecar

在数据文件的**完整文件名后面直接接 `.meta.yaml`**（不是替换扩展名），放在同一目录：

```
数据    R0007_W0012_ALL__FIT__NA__T202603051530_RUN0000.csv
sidecar R0007_W0012_ALL__FIT__NA__T202603051530_RUN0000.csv.meta.yaml
```

为什么是“接”不是“替换”：替换的话 `.csv` 和 `.tif` 会算出同一个 sidecar 名，
两个文件抢一个 sidecar。接上去则一一对应；多段扩展名本来就合法。

```yaml
derived_from:                       # 用了哪些文件，写完整文件名
  - R0007_W0012_D0003__MEAS__BUF1_DAQ1__T202603041030_RUN0000.csv
  - R0007_W0012_D0004__MEAS__BUF1_DAQ1__T202603041045_RUN0000.csv
input_sha256:                       # 从 manifest 抄，锁死用的是哪一版
  - 3f2a9c…
  - 8b41d0…
method: script                      # script | manual | ai_assisted
tool: "fit_pore.py @ commit a1b2c3d"   # 脚本算的必填，写清版本
params:
  model: linear
  r2_min: 0.98
reviewed_by: Li Ming                # 实名，必填
reviewed_at: "2026-03-05"
```

三条硬规则：

1. `derived_from` 里的每个文件**必须已经在库里**。引用一个不在库的文件 = 来源链断了。
2. `input_sha256` **从 manifest 抄，不要自己另算**。这样将来发现某个原始文件有问题，
   一条命令就能查出“哪些分析结果用过它”。
3. `method` 必须如实写。`ai_assisted` 不丢人，瞒着才危险。

衍生可以再衍生（汇总的汇总），`derived_from` 指向另一个 derived 文件即可；
链条可以一直走回原始数据。

### 3.2 四道闸门

`copy` 时对 `derived: true` 的文件逐项检查，缺一不收：

| # | 闸门 | 错误码 |
|---|---|---|
| 1 | 有配套 `.meta.yaml` | `SIDECAR_MISSING` |
| 2 | `derived_from` 非空，且每一项都能在 manifest 里查到 | `DERIVED_INPUT_NOT_IN_LIBRARY` |
| 3 | `input_sha256` 与 manifest 记录一致（引用的版本还在） | `DERIVED_INPUT_NOT_IN_LIBRARY` |
| 4 | `reviewed_by` 是实名（不是称谓） | `DERIVED_NOT_REVIEWED` |

**没复核的分析结果放哪？** 留在各人工作目录里，爱怎么迭代怎么迭代。
库是“经得起引用的东西”的家，不是草稿箱。

### 3.3 什么该入库

判据一句话：**这个文件会不会被别人引用、写进报告、或者当成下一步的输入？**

| 会 → 入库 | 不会 → 不入 |
|---|---|
| 交付给别人看的汇总表、图 | 调参过程中的几十版中间图 |
| 被写进报告/结论的拟合结果 | 一键就能重算的临时产物 |
| 下一步分析要拿来当输入的中间结果 | 探索性的、看一眼就扔的 |

标准是“会不会被引用”，不是“算得辛不辛苦”。库里每多一个没人看的文件，
将来找东西的人就多翻一页。

## 4. 账本：manifest.tsv

| 列 | 含义 | 为什么重要 |
|---|---|---|
| `sr_rel` | 库内相对路径 | 唯一落点 |
| `src_abs` | 入库那一刻的真实来源 | **“谁交的”唯一自动载体**；只记不改 |
| `sha256` | 文件哈希 | `verify` 逐条重算比对 |
| `size` | 字节数 | 快速发现截断/部分复制 |
| `copied_at` | 复制时刻 | 审计 |
| `partition` | data / derived | 分流核对 |
| `ingest_batch` | 哪一批收的 | 回答“交了 500 进了 480，那 20 个去哪了” |

四条纪律：

1. **每落一个文件，立刻写一行清单**，不要攒批。
   真实事故：跨网络复制 3000 个文件时崩溃，已落盘的文件没有清单行；重跑时判“已存在”
   又不再补行——这批文件永久缺失于账本，`verify` 从此把它们全报成“清单外文件”。
2. **只追加，不修改**。修订靠新批次，不靠改旧行。
3. **哈希在复制后重算并比对**，不一致就回退。
4. **`verify` 是独立的事实检查**：不信清单，逐条重算；也不信目录，扫出“清单外文件”。

## 5. 入库后变更：永不原地改

一句话总纲：**库内永不原地改——库外改好、换号重入、台账留痕。**
入库工具只有 check / copy / verify / void，没有改名、删除、覆盖命令：这是设计，不是缺功能。

| 要改什么 | 怎么走 |
|---|---|
| 字典条目（三件套） | 修订单 / 新号，见 [02-registry.md](02-registry.md) |
| 库内文件的**名字** | 名字 = 身份，入库即冻结；只有“登错了”才存在改名 |
| 库内文件的**内容** | 库外改好，**同名 T 不变、RUN 递增**，整份重入 |
| 被取代/登错的旧件 | **原地留库、保持只读**，作废状态记进作废清单；不移动、不物理删 |

三条不能省：

- **T 保持原时刻**：它记的是采集/编制那一刻，不是你改文件那一刻。
- **RUN 递增**：库里永远不会有第二份同名文件，“改”永远表现为“多一个新版本”。
- **旧 RUN 留库当历史**：引用旧版的人不会悬空。

**微小变更也走同一条路，没有捷径。** 内容改了一个字，哈希就变了，`verify` 就会报；
哪怕只是补一个字段，也要 RUN+1。变更的大小不改变流程，只改变自查范围：

| | 大改（整批重做） | 微小变更（改一两个文件） |
|---|---|---|
| 交付根 | 整个数据目录 | 可以只声明那一个子目录 |
| 自查 | 全量 | 只跑那个子目录 |
| 凭据 | 要 | **一样要**（新的一份） |
| copy | 整批 | 只对那个子目录跑 |
| 台账 | 一行 | **一样一行** |

省掉的是自查和复制的**范围**；凭据和台账一次都不能省——它们才是几年后
唯一说得清“这个版本哪来的”的东西。

### 作废：留件，不留洞

- 不移动、不删除；文件保持只读。
- 作废状态写进 `index/void_ledger.csv`：`voided_at, file, reason, who`。
- “现行版是哪个”以作废清单 + 台账为准，**不以库内文件存在与否为准**。
- 数据保留年限按你所在行业/机构的合规要求定；公开版默认“不删”。

## 6. 交付的 8 步（Steward 视角）

| 步 | 动作 | 卡住了会怎样 |
|---|---|---|
| S1 | 读交付人的 `_credential.txt`：时刻、根、件数、快照指纹 | 没凭据 / 旧快照 → 打回，不看内容 |
| S2 | `check`：射程内 / 合规数对不对得上凭据 | 对不上 → 多半没传完，退回 |
| S3 | `copy` 空跑：计划复制必须逐条等于 `_delivery_list.csv` | 差集非空 → 打回并列出差的文件 |
| S4 | 人工抽查 3–5 个：打开看内容对不对得上名字 | **不可代跑**，这是二级审查的实质 |
| S5 | 备份 manifest → `copy --apply` | 见错误码表 |
| S6 | `verify`：重算全库哈希 | 非 0 → 先对“去只读台账”；无记录 = 事故 |
| S7 | 写批次台账：批次号、交付人、交付根、实收、拒收、放行人 | — |
| S8 | 发回执：冻了什么、拒了什么、还剩哪几题要本人答 | — |

三条只对收库人说的话：

- **不设中转区**：直接从各人的共享目录跑 copy。`src_abs` 是“谁交的”的唯一自动载体；
  先拉到本地再入库，这条信息全库蒸发且不可逆。
- **跨人的顺序是硬的**：所有人的 `data` 全收完，再收所有人的 `derived`。
- **一次只收一个人，每批 verify 通过再进下一批。** 不要试图一天收完三个人。

## 7. 卡住了怎么办

| 现象 | 意思 | 动作 |
|---|---|---|
| `跳过 N 个` + 退出码 0 | 常态：还没改名的、不在射程的 | 不用管 |
| `跳过` 数接近总数 | 多半是路径里认不出属主，或人名单漏人 | 改到各人目录下跑，查名单 |
| `判不出分区` | 类型码没写 `derived` | 补标志位，不猜 |
| `PARTITION_MISMATCH` | 同名件已在另一个分区 | 查清是标志位后来改了还是当初放错，人工定 |
| `撞名且内容不同` | 库里已有同名、内容不一样 | 这就是变更：T 不变、RUN+1，整份重入 |
| `SIDECAR_MISSING` / `DERIVED_*` | 衍生四道闸门 | 补 sidecar / 先把来源入库 / 引用的版本变了 / `reviewed_by` 实名 |
| `复制后校验不一致，已回退` | 网络或磁盘问题 | 查网络后重跑 |
| `verify` 报被改 | 有人绕过只读改了库内文件 | 对“去只读台账”；无记录 = 事故 |
| `verify` 报清单外文件 | 有人没走工具直接往库里放东西 | 查来源；若是崩溃残留，重跑 copy 会自动补记 |

## 8. 诚实边界

- **库是一个普通目录，没有任何机制强制“只能通过工具写入”。** 只读是权限层，不是事务层；
  `verify` 只能事后发现。解法是入库走服务账号或独立主机，代价是显著运维复杂度。
  **触发重新设计的条件建议写死：出现第二个收库人，或单日入库 > 1000 文件。**
- **备份必须单独拍板。** 开卷快照 + 一份异机副本；保多久、谁验、多久验一次。
  如果暂时没有第二份，把“库是单点”写进风险记录，而不是当作没人提起的假设。
- **`manifest` 在几十万行以后要换 sqlite**；公开版只做到“能用”，不预建。
- **加密/密级只保留接口位。** 机密类型必须密文入库、双哈希账本这些规则见内部版；
  公开版默认关闭，避免把组织流程强加给 fork。

## 9. 命令

```bash
# 空跑
ai4s ingest copy workspaces/owner-a/SR_DATA --library library --registry registry

# 真收
ai4s ingest copy workspaces/owner-a/SR_DATA --library library --registry registry --apply

# 校验
ai4s ingest verify --library library

# 作废（留件）
ai4s ingest void --library library --name <完整文件名> --reason "被 RUN0001 取代" --who "Li Ming"
```
