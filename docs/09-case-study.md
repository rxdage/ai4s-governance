# 09 · 脱敏案例：一个 5 人 AI4S 团队的四个月

> 这一节讲“这套东西是怎么长出来的”，不是“你应该照抄”。
> 行业细节已抽象为“微纳器件 + 湿实验 + 仿真”；数字保留，因为它们是方法有效性的证据。

## 1. 背景

- 团队：5 名研发 + 1 名兼职管理员（兼数据 owner）。
- 产出：器件流片、湿实验测量、表征（图像/谱）、仿真与拟合、对外报告。
- 数据：两台存储服务器、10 个个人目录，**1,751,067 个文件**。
- 工具：Python + 共享盘 + 一个聊天机器人；没有专职数据工程、没有 LIMS。
- AI：每人一个本地 agent，能读文件、跑脚本、改 yaml。

## 2. 起点：三种命名同时存在

扫描后发现，同一个团队里至少有五种“命名方言”：

| 方言 | 特征 | 机器可读性 |
|---|---|---|
| 破折号分区 | `0509-R26_1-4.8nm-...-pH8.pbf` | 高（37–54% 整条匹配） |
| 空格分区 | `R36_W2_42 100nM_polyT ... 200mV 50kHz_0000.abf` | 中高（93.7% 符合文法，但字段靠自然语言） |
| 纯序号 | `dna034.abf`、`200499.abf` | 极低（87% 纯序号，条件全在目录名） |
| 缩写码 | `KYKTC004.abf` | 极低（零字段，缩写表缺失） |
| 仪器自动名 | `Channel_10_for_filterData_2026-07-22-17-00-31.csv` | 中（只有 die + 测项） |

**关键发现**：问题不在“大家不肯改名”。是**没有一套能同时满足机器和人、且迁移成本可承受的规则**。
任何新规范必须先解释“为什么旧名字不行”，再给一条能逐步迁移的路。

## 3. 设计：先扫描，后规范

第一版规范不是拍脑袋写的。先做了三件事：

1. **全量词汇扫描**：1,751,067 个文件，按 `_ - . + ( ) , ; # &` 切词，
   统计 token 频率、槽位覆盖率、同义组。
2. **每人的文法反推**：把每个人事实上的命名文法写成正则，算覆盖率。
3. **“条件在哪”审计**：文件名、目录名、内容头，各承载多少条件。

结论直接改变了设计：

- 有人的条件全在目录名 → 规范不能假设“条件都在文件名”，必须给目录名一个合法位置
  （最终用 `LIVEDOCS/` + 四区命名快照解决）。
- 有人的序号是仪器自动分段号 → 不能当条件码，必须折叠成一个 `DAQ` 类。
- 同一批数据有 3 套编号（`R37_W4`、`R037_W04`、`R37-W04`）→ 必须定死 4 位补零。

## 4. 规范：四区制

最终定下来的就是本仓 [01-naming.md](01-naming.md) 的四区制。几个关键决策：

- **由三区升四区**：把“类型”和“条件”拆开，因为它们是两个独立变化维度。
- **取消 P 槽位**：会上逐个确认“一个 RUN 只对应一个文件”，P 永远是 P0000，纯冗余。
- **ALL 只在 W/D**：整片/整批级汇总需要一个合法写法，但不能让它和单颗混写。
- **R0000 库级**：参数表、协议、跨批总结不挂任何批次。
- **条件码 ASCII 排序**：不承载语义，机器一行代码就能判；乱序只提示、不代改。

配套工具：解析器（内置正反例自测）、注册表体检、签字工具、改名助手（五道闸门 + 改名日志）、
入库工具（check/triage/copy/verify）、自查包（含内容交叉验证）。

## 5. 入库：从“交文件”到“交凭据”

最初的交付是“微信说一句 + 把文件夹拷到共享盘”。问题是：收库人不知道收了什么、
有没有收全、内容对不对。

改成：

```
owner 自查 → PASS 凭据 + 交付清单 → 传到自己的 SR_DATA/
→ Steward 验凭据/空跑对账/抽查 → copy --apply → verify → 台账 → 回执
```

三个设计点最有用：

1. **凭据由程序生成**，带字典快照指纹；对不上就打回。
2. **空跑计划必须逐条等于交付清单**；差集就是“没传完/多传了”。
3. **回执卡**：告诉交付人“冻了什么、拒了什么、还剩哪几题要本人答”。
   没有回执，交付人不知道能不能动自己那份。

## 6. 认知层：模型库与证伪台账

数据能找到了，下一步是“结论凭什么可信”。

- 15 个从第一性物理推导的模型，分 A/B/C 三场景；每个模型八段、带可证伪判据、
  两项分数（重要性 /10、置信 L0–L3）。
- 一条被真求解器证伪的结论（边缘增强 6.1×）完整作废：保留原脚本作历史资产、
  标注“不可作锚点”、写清“本类模型不支持这个数，不是真实器件没有边缘增强”。
- 证伪台账累计 **117 条**（95 条电容系列 + 22 条平台系列），字段包括
  `claim / status / verdict / correction / caveats / residue / scope / source`。
- 一次对抗复核：**12 条初稿，11 条被推翻**；27 个 agent、约 256 万 token、343 次工具调用。
- 另一次月度分析：6 条承重结论，**5 条被推翻**，只留幸存结论。

比“推翻了 11 条”更重要的是：**推翻之后旧数字还会不会复活**。
所以每条台账都有 `residue`（旧值还散落在哪些文件），并入后要巡查一遍。

## 7. 数字

| 指标 | 数值 |
|---|---|
| 扫描文件 | 1,751,067 |
| 数据类文件 | 1,159,750 |
| 仪器原始采集 | 17,909 |
| 类型码 | 39（7 个 derived） |
| 单源库某时点 | 1,592 个数据文件 + 135 个 sidecar |
| 证伪台账 | 117 条 |
| 一次复核 | 12 条初稿 → 11 条推翻 |
| 一次 AI 整理交付 | 145 个语法错、192 个未注册码、1 份 YAML 解析失败 |
| 两个月自我推翻 | 7 次 |

### 7.1 一次 before/after 体检（脱敏）

用 `ai4s audit --names` 对几组目录做只读体检，只看文件名，不读内容：

| 目录 | 类型 | 数据文件 | 可解析 | 重复名 | sidecar |
|---|---|---:|---:|---:|---:|
| 旧归因测试包（老编号 + 中文名） | 旧数据 | 60 | **0%** | 0 | 0 |
| 早期测试批次（原始采集，未改名） | 旧数据 | 171 | **25.7%** | 0 | 0 |
| 合成乱样本（见 `examples/build_messy_lab.py`） | 合成 | 115 | **13%** | 5 | 0 |
| 一位 owner 的 `SR_DATA`（早期交付） | 已改名 | 926 | **100%** | 0 | 0 |
| 另一位 owner 的 `SR_DATA`（改名后） | 已改名 | 931 | **100%** | 0 | 123 |
| 一份交付包（含 sidecar） | 已改名 | 122 | **100%** | 0 | 95 |
| 一份报告/配图交付包（不是数据根） | 非数据 | 221 | **0%** | 2 | 0 |

这张表里有两个 0%，含义完全不同：

- 旧测试包的 0% 是问题。它是数据，但名字还停在老编号。
- 报告包的 0% 不是问题。它是给人看的报告和配图，本来就不该按数据命名。

中间那个 25.7% 是“改到一半”的批次。在这几个样本里，改名更像二元状态：没改的落在 0–26%，改完的落在 100%。所以先判断一个目录是不是**数据根**，再看它有没有改完。

## 8. 失败与修正

### 8.1 “AI 整理过了”不等于对

三位同事都用 AI 整理过，仍然交上来 145 个语法错、192 个未注册码、1 份坏 YAML。
**修正**：把“PASS 由程序判定”写成铁律；AI 的自我评估不算证据。

### 8.2 假 APPROVED

曾有 11 个条目的 `approved_by` 被填成“合伙人”，实际无人批准；
后来一次 AI 代签导致整批 **162 条**签字被撤销重签。
**修正**：签字必须实名 + 日期；公开版进一步把签名绑定到内容哈希。

### 8.3 手拼卡没有底稿

两张卡是手拼的，没写底稿；同事照卡回复，机器人整条拒收，还回了一句“这张卡还没群发”——
号没抄错、卡也发了，**两句都不是事实，却把锅甩给了当事人**。
**修正**：卡只由工具发；手拼必须补底稿；一个题号只能配一个选项。

### 8.4 收库崩溃导致清单缺行

跨网络复制 3000 个文件时崩溃，已落盘的 file 没有 manifest 行；重跑判“已存在”又不再补行。
**修正**：每落一个文件立刻写一行 + fsync，不攒批。

### 8.5 worktree 陷阱

克隆出来的 worktree 里有一份路径酷似主仓的 `dict/`；在那里改一行，体检照样全绿，
发出去的包一个字不变。**修正**：真值链 + 五落点哈希巡检；文档里明确“长得像真值的旧”最危险。

### 8.6 移动文件夹没有任何代码在守

工具不看目录，文件被挪了既不报错也不告诉任何人。
**修正**：不靠“拦住”，靠“让违规无害”——指纹改成 basename，挪动不再破坏交付；
真正不可逆的只有删除和覆盖，那两项用“唯一允许改名”+ 改名工具闸门挡住。

## 9. 哪些做对了

1. **先扫描后规范**，不是先写一本规范再推广。
2. **YAML 是唯一真值**，文档只是解释；工具与文档冲突时以 YAML 为准。
3. **工具只提示、不代改**；改名是人的决定。
4. **凭据由程序生成**，把“AI 说应该能过”变成“退出码 0”。
5. **回执卡**：把“收完了”变成“谁、冻了什么、还欠哪几题”。
6. **证伪台账 + residue**：让死结论有地方待，且能被找到。
7. **周总结回看上一页**：唯一能证明“在往前走”的机制。

## 10. 哪些没解决

- **单点 Steward**：一个人扛全部复杂度，没有 plan B。
- **库是普通目录**：没有机制强制“只能通过工具写入”，verify 只能事后发现。
- **备份未完全落地**：开卷快照 + 异机副本的保留策略需要单独拍板。
- **manifest 规模**：几十万行以后要换 sqlite。
- **模型未达 L3**：15 个模型最高 L2，没有和自己的实测数据标定。
- **加密只覆盖增量**：已发出去的存量收不回；文件名本身不加密。

## 11. 迁到你的团队要改什么

| 保持 | 改 |
|---|---|
| 四区文法、`__`/`_` 分隔、全大写、200 字节 | R/W/D 的语义映射 |
| 先注册后使用、哈希签名 | 签字人角色名 |
| data/derived 分区、sidecar 四道闸门 | sidecar 的必填字段（按你的复现需求加） |
| 复制入库、manifest、只读、verify | 存储路径与权限模型 |
| 凭据 + 回执 + 巡检 + 周总结 | 机器人平台（飞书/Slack/Teams/本地） |
| 证伪台账 + residue | 域代码（DEP-XXX）与评审人 |

**不要照抄的**：具体类型码、条件 class、行业参数、加密流程、内部人名/路径。
这些是案例的“皮”，不是方法。
