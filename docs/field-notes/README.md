## 发布顺序

1. 先发第 1 篇：它最具体、门槛最低，适合建立“这团队真跑过”的印象。
2. 再发第 2 篇：它回答“你们是怎么长出来的”，适合 HN 和 LinkedIn。
3. 第 3 篇回答“买了没人用怎么办”，最适合创业公司。
4. 最后发第 4 篇：它最技术、最省钱，适合 CTO 群和 HN。

## 每篇的规则

- 开头是一个具体下午/具体文件，不要用行业趋势开场。
- 中间只放一个可复制的产物：一张表、一个命令、一份报告。
- 结尾不写“欢迎 star”，写“如果你有类似的目录，我可以免费跑一份体检”。
- **不写供应商排名**。模型版本一个季度就变；写机制，不写“谁比谁好”。
- 不写真实人名、公司、批次、路径。
- 中文和英文分别写，例子不同；不要机翻。
