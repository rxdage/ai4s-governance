# 01 · 四区制文件名

> 机器真值：[`spec/filename-schema.yaml`](../spec/filename-schema.yaml)。
> 本文与它冲突时，以 YAML 为准，并回头把本文改一致。

## 1. 一眼看懂

```
R0007_W0012_D0003__MEAS__BUF1_DAQ1__T202603041430_RUN0000.csv
└──── 第 1 区 身份 ────┘ └第2区┘ └─第 3 区 条件─┘ └──── 第 4 区 时序 ────┘└扩展名┘
      谁（哪个物理对象）    什么文件     什么条件下        何时、第几轮
```

- 区之间：**双下划线 `__`**。
- 区内：**单下划线 `_`**。
- 四区一个都不能少；缺任何一区、或任何一区格式错误，就是非法命名。
- 第 1–4 区**全部大写**；只有扩展名允许小写。

## 2. 四个区

### 第 1 区 · 身份

格式固定为 `R{4}_W{4}_D{4}`，三段顺序固定、缺一不可。

| 前缀 | 原始含义 | 泛化含义（AI4S） | 例子 |
|---|---|---|---|
| `R` | 批次 / run | 实验批次、流片批次、campaign | `R0007` |
| `W` | 晶圆 | 样品、片子、样本 | `W0012` |
| `D` | die | 个体、芯片、孔、重复单元 | `D0003` |

> **为什么保留 R/W/D 而不是改成 C/S/U**：这套规则在真实团队里已经跑了半年，
> 工具、贴纸、wafermap、历史文件名都按 R/W/D 写。泛化时只改“语义映射”，
> 不改字母，迁移成本最低。你的团队若没有“片/颗”概念，把 D 当成 replicate 即可。

规则：

- 数字**一律 4 位补零**：`R7` ❌、`R0007` ✅。
- `R/W/D` 是保留前缀，不可注册、不可更改。
- **编号起点可配置**：新团队一般从 `0000` 起；有历史编号的团队把
  `semantics.numbering.zero_allowed_from` 调到“从哪一批开始允许 0000”即可。
- `ALL` **只允许出现在 W、D 两个槽位**，R、T、RUN 永远禁止：
  - 整片级：`R0007_W0012_ALL` —— 这片样品的整体数据
  - 整批级：`R0007_ALL_ALL` —— 这批的整体数据/笔记
  - `W=ALL` 时 `D` 必须也是 `ALL`；禁止 `R0007_ALL_D0003` 这类混写
  - ALL 不支持部分选取：要么单值，要么 ALL
- **库级文件**（不挂任何批次的参数表、跨批次总结）固定写 `R0000_ALL_ALL`。
  `R0000` 保留，永不用于真实批次。
- 外购对照/参照材料同样按库级写 `R0000_ALL_ALL`，样品明细记台账备注，不进文件名。

### 第 2 区 · 类型码

一个词说明“这是什么文件”。

- 文法：**2–15 个纯大写字母，不得含数字**（`^[A-Z]{2,15}$`）。
- 只有一级，不存在 class-instance 结构。
- **按内容注册，不按人**：同类数据共用同一个类型码，不因为换了操作者就另起炉灶。
- 必须先在 `registry/types.yaml` 注册并签字，才能出现在归档文件名里。
- 保留字禁止注册：`NA` `NAN` `ALL` `RUN` `CH` `UNMAPPED`。

示例（不是规定，按你的实验室内容定）：

| 类型码 | 含义 | derived |
|---|---|---|
| `MEAS` | 仪器测量数据 | false |
| `IMG` | 图像/显微图 | false |
| `CALIB` | 校准与标定记录 | false |
| `SUMMARY` | 汇总表 | true |
| `FIT` | 拟合结果 | true |

> **纯字母 vs 字母+数字**：类型码纯字母、条件码字母+数字。机器和人都能一眼分层，
> 也让“这是类型还是条件”不需要查表就能判断。

### 第 3 区 · 条件码

说明这个文件是在**什么条件/参数**下产生的。三层注册，只有 code 进文件名：

| 层 | 是什么 | 例 | 去哪 |
|---|---|---|---|
| class | 条件的类别 | `BUF`（缓冲液） | 只进注册表 |
| **code** | 类别下的编号 | **`BUF1`** | **进文件名** |
| instance | 该编号的具体参数 | 10 mM Tris、pH 8.0、1 M KCl… | 只进注册表 |

规则：

- class、code 都必须注册，instance 必填；批准后才能用。
- code 文法：class 名 + 数字；数字**允许 0、不补零、无前导零**
  （`BUF0`、`BUF1`、`BUF12` 合法；`BUF01` 非法）。
- 多个 code 之间按**整个 code 的 ASCII 逐字节比较**排序：
  `BUF1_DAQ1_SAMP1` ✅，`DAQ1_BUF1_SAMP1` ❌。
  顺序不承载语义；工具发现乱序**只提示、不代改**。
- **同一 class 最多出现一次**（不会出现 `BUF1_BUF2`）。
- 不需要条件时写字面量 **`NA`**，且 **NA 必须单独充当整个第三区**（禁止 `NA_BUF1`）。
- **instance 完整性（整套体系的地基）**：instance 必须完整到“**同 code 即同参数集**”的程度——
  凡会影响结果、能区分两次实验的参数（判别性参数），一个都不许省。
  **任何参数变更 = 注册新 code（`DK1 → DK2`），绝不改旧 code 的含义。**
- 什么叫“写不下”：只有当参数本体是**文件级内容**（逐点电压序列、完整仪器配置导出、
  大表格、曲线）时才算。这时把大参数体整体放进对应的 `*PAR` 文件，instance 里仍要写
  **判别性摘要 + 该文件的完整文件名**。不允许整个 instance 只留一个指向。

### 第 4 区 · 时序

格式固定为 `T{12}_RUN{4}`，两段都必写。

- **T：人工核对后手写的时间**，不取系统自动生成的创建时间。
  布局 `YYYYMMDDHHMM`，共 12 位，最后两位是分钟。
  - 必须是真实日期：`T202613…` 这类假日期直接被拦。
  - 建议统一时区，并在 `lab.yaml` 里写明。
- **RUN：轮次**——同一对象、同一类型码、同一条件组下的**第几次执行**，从 `0000` 起。
  - `RUN0000` 同时表示“第一轮”和“无轮次概念”，有意合并，不作区分。
  - **RUN 是唯一的计数槽位**。一次采集吐出多个文件 → 递增 RUN；同一分钟撞名 → 下一个 RUN。
  - 旧规范里的 `P0000`（轮内序号）已取消：一个 RUN 只对应一个文件时它是纯冗余。

## 3. 字符集、长度、唯一性

- 文件名主体只允许 `A-Z 0-9 _ .`（扩展名允许小写字母）。
- 明确禁止：空格、连字符 `-`、括号、中文及中文标点、`+ , ; # &`。
- **严禁靠大小写区分语义。**
- 完整文件名（含扩展名）**≤ 200 字节**。
- 完整文件名在库内**必须唯一**：撞名拒收，不覆盖。
- 库内**不按人、不按类型、不按晶圆再分子目录**：`分区/R{4位}/完整文件名`，一共三层。
  平铺是有意的——“同名必然在同一路径相撞”这道保护，靠的就是平铺。浏览库请查 `manifest`。

## 5. 反例与错误码

| 反例 | 错在哪 | 错误码 |
|---|---|---|
| `R37_W1_D2__MEAS__NA__T202603041430_RUN0000.csv` | 没有补 4 位 | `ZONE1_SYNTAX` |
| `R0007_ALL_D0003__…` | W=ALL 但 D 不是 ALL | `ZONE1_ALL_MIX` |
| `R0000_W0012_D0003__…` | 库级却写了具体 W/D | `ZONE1_LIBRARY_MIX` |
| `R0038_W0000_D0001__…`（若该批从 0001 起编） | 0000 不合法 | `ZONE1_NUMBERING` |
| `…__BUF01__…` | 条件码补零 | `CODE_SYNTAX` |
| `…__BUF1_BUF2__…` | 同 class 出现两次 | `COND_DUPLICATE_CLASS` |
| `…__NA_BUF1__…` | NA 未独占 | `COND_NA_MIXED` |
| `…__meas__…` | 正文出现小写 | `BODY_NOT_UPPERCASE` |
| `…T202613041430…` | 假日期 | `TIME_INVALID` |
| `…_RUN0000_P0000.csv` | 旧 P 槽位 | `LEGACY_P_SLOT` |
| `…_RUN0000`（无扩展名） | 缺扩展名 | `EXT_MISSING` |
| `R0007-W0012-D0003__…` | 连字符 | `CHARSET_INVALID` |

## 6. 为什么是这些规则

1. **为什么不用数据库/DAM？**
   小团队没有 DBA，也没有预算。文件系统是唯一不会“服务挂了就全没了”的存储；
   把语义放进文件名，检索、备份、迁移、给外部合作方拷贝都不依赖任何软件。
2. **为什么四区而不是一张大表？**
   四个问题（谁/什么/什么条件/何时）各自独立变化。分区让每一段可以单独校验、
   单独扩展，也让错误定位到具体一段。
3. **为什么条件码只写 class+数字？**
   参数全写进名字会爆炸（pH/浓度/电压/采样率/序列……），且无法保证顺序一致。
   class+数字把“参数细节”锁进注册表，名字只留稳定标识。
4. **为什么 T 要人手写？**
   系统创建时间会被复制、解压、改名重置；它记录的是“文件什么时候落到这台机器”，
   不是“数据什么时候被采集”。T 是实验事实，必须由人核对。
5. **为什么 RUN 从 0000 起、允许缺号？**
   从 0000 起让“第一轮”和“无轮次”统一；缺号要当成**要本人回答的问题**，不要当成错误
   （丢了？漏传？有意不交？），所以它是 WARN 而不是 ERROR。

## 7. 机器契约怎么用

```bash
ai4s naming selftest
ai4s naming check "R0007_W0012_D0003__MEAS__BUF1_DAQ1__T202603041430_RUN0000.csv" \
  --registry examples/demo/registry
```

解析器从 `spec/filename-schema.yaml` 读取分区正则、字符集、上限、编号起点、
保留字和错误码。改规则只改 YAML，然后跑 `ai4s naming selftest`；不要在两处各写一份。

## 8. 迁移旧文件

1. **先定 cutoff**：哪一天之后的新文件必须用新规则；之前的按批迁移，不搞“一夜之间全改”。
2. **先扫描、后设计**：把现有文件名分词、统计槽位覆盖率，再决定哪些字段进名字。
   （真实案例：175 万文件扫描后发现“条件写在目录名里”的那批，文件名根本不可解析。）
3. **改名必须走工具**：预演 → 本人点头 → `--apply` → 自动写改名日志（原名唯一留档）。
   工具至少要有五道闸门：新名合文法 / 码已注册且签字 / 目标不存在 / 清单内不撞名 /
   新旧身份区一致（改身份要单独确认）。本仓内置：

   ```bash
   ai4s rename --root <数据目录> --plan 改名清单.csv --registry registry
   # 预演通过、本人点头后：
   ai4s rename --root <数据目录> --plan 改名清单.csv --registry registry --apply
   ```

   任何一行不过，**一个文件都不会动**（all-or-nothing），并生成
   `_rename_log_<时刻>.csv`。
4. **改名不改内容**：扩展名变了就别走改名；另做一份文件，另走一次入库。
5. **库内不改名**：入库即冻结。名字错了只能“登错”这一种情况，走台账 + 重新入库，
   旧件原地留库。
