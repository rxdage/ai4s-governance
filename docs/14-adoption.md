# 14 · 教化：五个人是怎么开始用的

> adoption 不是“读过文档”。它是第一个 PASS，第一次自己发起自查，第一次回执，第一条提案，
> 第一次向别人解释规则。
>
> 我们当时没有把 adoption 做成指标。这一章一半是重建，一半是“下次会怎么量”。

## 0. 五个里程碑

| 里程碑 | 怎么算 | 为什么重要 |
|---|---|---|
| M1 第一个 PASS | 本人交付根出现 `_验收凭据.txt` | 第一次“程序说行”，不是“AI 说行” |
| M2 第一次自己发起自查 | 没人催，本人主动跑 | 从“被检查”变成“我的流程” |
| M3 第一次回执 | 按格式回一题 | 机器能认，闭环成立 |
| M4 第一条提案 | 在 `REGISTRY/` 提一个新码 | 从“用规则”变成“改规则” |
| M5 第一次教别人 | 本人向新同事解释一条规则 | 文化开始复制 |

## 1. 一条重建的曲线

| 时间 | 发生了什么 | 谁推动 | 卡在哪 |
|---|---|---|---|
| 第 0 周 | 四区制定稿；0 人使用 | Steward | 大家觉得“又要多一套规矩” |
| 第 1 周 | 自查包发布；第一位同事跑出第一个 PASS | 一位愿意试的 owner | 145 个语法错、192 个未注册码；AI 说“应该能过” |
| 第 2–3 周 | 第二、三位同事开始用；主要靠人陪跑 | owner + 自己的 AI | “我的 AI 说没问题”；改名不敢点 `--apply` |
| 第 4 周 | 第一批回执发出；约 3/5 有 PASS | Steward | 凭据快照对不上；包换得太勤 |
| 第 6 周 | 第四位同事加入；周总结固定 | Steward | 周总结变成流水账，上周待办没人回看 |
| 第 8 周 | 第一次没人催的自查；第一次不回怼的回执 | owner | 仍有人把 WARN 当“改掉就好” |
| 第 3 个月 | 一次通过率上升；一类失败关闭后 0 复发 | 全员 | 单点 Steward 开始变成瓶颈 |
| 第 4 个月 | 新人用“包 + AI 提示词”入职；约 1 天出第一个 PASS | 新人 + AI | 老人仍在用旧习惯处理例外 |

> 除了“145/192”“162 条签字”“0 复发”这些有记录的数字，其他是重建的。
> 我们当时没量 M1–M5，这是下一版要补的仪表。

## 2. 前 30 分钟决定 adoption

新人不会因为一份 40 页的规范而 adoption。他会在前 30 分钟决定“这东西是不是给我添麻烦”。

所以前 30 分钟只放四样东西：

1. **一条命令**：`ai4s check <我的目录>`。
2. **一句人话**：错在哪、该做什么，不是错误码。
3. **一个人**：出问题能问谁（Steward 或一位 champion）。
4. **一张绿卡**：没事也发卡，让“没收到卡”本身成为信号。

规范可以以后读。第一个 PASS 越早，后面越容易。

## 3. 教化机器（不是培训课）

让五个人开始用的，是这些“把决定变少”的东西：

| 机制 | 减少了什么决定 |
|---|---|
| AI 提示词块（可直接贴） | “我该让 AI 做什么、不许做什么” |
| 自查报错写“原因 / 该做” | “这个错是什么意思” |
| 回执卡 🔴/🟡 + “整张卡复制给你的 AI” | “哪些我能做、哪些必须问人” |
| 四夹制（SR_DATA/REGISTRY/LIVEDOCS/PERSONAL） | “这个东西该放哪” |
| 明令“不要整理文件夹” | “我是不是该把目录理一理” |
| 没事也发绿卡 | “没消息是不是出事了” |
| 变更只有一条路（T 不变、RUN+1） | “这次改动走哪个流程” |

每多一条规则，就多一个决定。我们后来只保留必须的决定。

## 4. 指标：下次一定要量

| 指标 | 定义 | 为什么 |
|---|---|---|
| Time to first PASS | 第一次拿到包 → 第一份凭据 | 最直接的 adoption 门槛 |
| Rounds to first PASS | 第一次跑 → PASS 跑了几轮 | 衡量报错措辞和工具友好度 |
| Self-initiated ratio | 没人催的自查 / 总自查 | 从“被检查”到“我的流程” |
| WARN answer latency | WARN 发出 → 本人答复 | 卡住收库的主要因素 |
| Receipt reply rate | 回执卡发出 → 按格式回复 | 闭环是否真的闭合 |
| Recurrence | 同一类失败关闭后是否再出现 | 唯一能证明“在往前走”的指标 |
| New-hire time to first PASS | 新人入职 → 第一份凭据 | 教化是否可以复制 |

### 用工具量

`ai4s check` 每次跑的时候可以追加一行日志；`ai4s adoption` 从日志、回执和提案里算 M1–M4：

```bash
# 每次自查写一行（建议写进本人的脚本/别名，不要靠记）
ai4s check <SR_DATA> --registry registry --library library \
  --log state/selfcheck_runs.jsonl --person owner-a

# 出报告
ai4s adoption --config lab.yaml --out state/adoption_report.md
```

报告长这样：

```
People                 5
M1 first PASS          4
M2 second day          3
M3 receipt             3
M4 proposal            1
Median days to first PASS   3.5
Median rounds to first PASS 2
Active in last 30 days      4
```

M1–M4 自动；**M5 只能人工观察**（他有没有向别人解释一条规则）。
如果还没有日志，工具会用 `_credential.txt` 的 mtime 兜底，只能算 M1，算不出 rounds 和 time-to-first-PASS。
所以第一件事是：**把 `--log` 写进每个人的自查命令**。

第一次真实体检：一位 owner 的 `SR_DATA` 有 931 个数据文件，100% 可解析；同一周跑一份旧测试包，60 个文件，0%。这不是全公司，但能看出“改完的”和“没改的”差距。

## 5. 培训格式：15 分钟，三个动作

不要讲规范。拿他自己的 5 个文件，做三件事：

1. **命名**：现场改 5 个文件，让他看到“机器能读”和“人也能读”。
2. **自查**：跑一次 `ai4s check`，让他自己读报错，不要替他读。
3. **回执**：给他一张回执卡，让他回一题。

规则：

- **他操作，你看**。不要替他点鼠标。
- 录一个 2 分钟的视频，比写 10 页文档有用。
- 作业：改 5 个文件、跑一次自查、回一张卡。做完再谈规范。
- 第二次只讲他卡住的那一条，不讲全套。

## 6. 什么拖慢了 adoption

- **145 个语法错、192 个未注册码**：这不能怪人笨。工具报错没有“该做”，人只能猜。
- **AI 的自信**：“应该能过”让本人以为不用跑。
- **手拼卡没有底稿**：同事照卡回了，机器拒收，还怪他抄错号。
- **WARN 被当成“改掉就好”**：一改就是编数据，越帮越忙。
- **包换得太勤**：凭据快照对不上，收库打回，信任消耗。
- **单点 Steward**：一个人扛全部复杂度，他一忙，全员停。
- **文档太长**：没人读；读的人也不一定照做。

## 7. 如果重来

1. **从第一天就量 M1–M5**，不要等“系统稳定了再说”。
2. **第一批只收 10–50 个文件**，包含一个衍生件；先别想着收完。跑通闭环就算赢。
3. **先找一个 champion，再配对第二个人**；不要一次培训五个人。
4. **两周不换包**；要换就一次换完，别让凭据追着包跑。
5. **把“没 PASS 不许传”写成硬规则**，但把报错写成“人话”。
6. **每周只问一句**：这周是在往前走，还是在原地重做？
